# AgentWall

An interactive web playground for inspecting AI tool calls, experimenting with safety policies, and visualizing secret redaction. It demonstrates a proposed runtime firewall through sample shell, SQL, and MCP-style requests.

## Current implementation

The repository implements a browser-based policy evaluation demo, not an installed shell wrapper or a live MCP proxy. It parses submitted text and produces local verdicts and JSON-RPC-shaped traces. Custom commands are not executed: their output is generated by the demo.

The gateway switches, daemon toggle, snapshot controls, and generated TOML describe a proposed runtime workflow. They do not connect to gateways, enforce network restrictions, capture files or databases, or restore real snapshots. The repository does not provide the `agentwall -- command` CLI advertised by parts of the UI.

## Features

- Inspection playground for supplied scenarios and custom tool-call text.
- Shell parsing, SQL checks, and checks for MCP filesystem paths.
- Configurable policies covering destructive commands, Git operations, unbounded SQL mutations, network destinations, obfuscated execution, and sensitive files.
- Secret-pattern scanning and tokenized redaction of sample outputs.
- Inbound, policy, and result frames for explaining a verdict.
- Audit dashboard, vault previews, gateway views, snapshot metadata, and TOML export.

## Explore the demo

1. Open `/intercept` and run a supplied scenario.
2. Compare the original request, findings, and result frames.
3. Toggle policies at `/policies` and repeat the scenario.
4. Inspect `/audit` and `/vault`.
5. Visit `/config` to copy the generated configuration or reset demo state.

State is persisted in browser localStorage under `agentwall-v1`. It includes policies, up to 80 audit events, vault previews, gateway state, and snapshot metadata. Audit commands can contain sensitive text; use synthetic inputs rather than real credentials.

## Technology and structure

React 19, TypeScript, TanStack Start/Router, Vite, Tailwind CSS 4, Zustand, and Radix UI.

| Path | Responsibility |
| --- | --- |
| `src/routes/` | Dashboard, interception, policies, audit, vault, snapshots, gateways, and config |

| `src/lib/engine/samples.ts` | Seed data and scenarios |
| `src/lib/store.ts` | Browser persistence and demo actions |

## Limits and next steps

The text-based inspections are heuristics, not a security boundary. Displayed latency is adjusted and randomized; it is not a production benchmark. Token “rehydration” currently marks a forwarded request with a comment rather than retrieving an authorized secret from a secure vault. Snapshot actions change metadata only.

A real gateway would need transport interception before execution, canonical path handling, robust language parsing, protected secret storage, destination-level authorization, actual egress enforcement, durable auditing, and adversarial tests.

## Run locally

Use Node.js 22.12+ and npm.

```bash
git clone https://github.com/pranavgawasproject/agentwall.git
cd agentwall
npm ci
npm run dev
```

Open http://localhost:8080. The npm scripts load the checked-in app flags through `scripts/with-app-env.mjs`; use these scripts rather than invoking Vite directly.

The checked-in configuration disables authentication and database deployment. The demo's application state lives in the browser; no model API key or database is required for its core workflow. The repository also includes Grok-specific authentication, connector, PWA, and deployment scaffolding. Those integrations depend on the original platform environment and need separate configuration outside it.

The migration script skips when `DATABASE_URL` is absent. If configured and root SQL migrations exist, the build can apply them. Keep deployment credentials in the environment. The current test command primarily covers scaffold helpers; it does not establish correctness of the product's detection engine.
